# Memory Policy Lab — Windows UI

โปรแกรมภาษา C สำหรับ Windows 10/11 แบบ 64-bit พื้นสีขาว ปุ่มสีน้ำเงิน ใช้ engine FIFO, LRU, Optimal และระบบค้นหาเดิม

## เปิดใช้งาน

ดับเบิลคลิก **memory_policy_lab.exe ที่อยู่ข้างไฟล์นี้** ได้ทันที ไม่ต้องเปิด Terminal ไม่ต้องใช้ GCC หรือ build ใหม่

หากได้รับไฟล์ ZIP ให้แตกไฟล์ทั้งโฟลเดอร์ก่อนเปิด เพื่อให้ปุ่มโหลดตัวอย่างหาโฟลเดอร์ `examples` เจอ

เริ่มทดลองเร็วที่สุด: เลือกตัวอย่าง LRU wins → โหลดตัวอย่าง → รันทั้งหมด โปรแกรมตั้งให้ใช้ 2 frames อัตโนมัติ ตัวอย่าง FIFO wins และ Belady ตั้งให้ใช้ 3 frames

โฟลเดอร์นี้เป็นเวอร์ชัน UI ใหม่ แยกจากโปรเจกต์ต้นฉบับใน D:\OS Project จึงต้องเปิด EXE ในโฟลเดอร์นี้ การเปิด EXE เดิมใน D: ยังเป็น Terminal ตามเดิม สามารถย้ายทั้งโฟลเดอร์นี้ไปที่ที่ต้องการได้

## หน้าต่างและฟังก์ชันเดิม

| เมนูเดิม | ส่วนใน UI | โค้ดที่เกี่ยวข้อง |
|---|---|---|
| 1 Load | ปุ่มเปิดไฟล์ ใช้หน้าต่างเลือก `.txt` เริ่มต้นที่ `results` | `open_file`, `load_path`, `load_references_stream` |
| 2 Frames | หน้า Simulation → จำนวน Frames 1–10 | `action`, `frames` |
| 3 Algorithm | หน้า Simulation → FIFO / LRU / Optimal | `action`, `algo` |
| 4 Step by step | เริ่มทีละขั้น → ขั้นถัดไป / รันที่เหลือ / หยุด | `simulate_start`, `show_trace`, `simulate` |
| 5 Run all | รันทั้งหมด | `simulate_start`, `simulate` |
| 6 Compare | หน้าเปรียบเทียบ → เปรียบเทียบ / แสดงทั้งหมด → ตารางสรุป | `summary` |
| 7 References | ปุ่มดูชุดข้อมูล เปิดหน้าต่างข้อความทั้งหมด คัดลอกได้ | `show_refs` |
| 8 Frame sweep | หน้าจำนวน Frames → เปรียบเทียบ 1–10 Frames → ตาราง | `sweep` |
| 9 Search | หน้าค้นหาชุดข้อมูล มี Condition, Page IDs, Exact length, Frames, Search limit | `start_search`, `search_references`, `finish_search` |
| 10 Side by side | หน้าเปรียบเทียบ → ตาราง FIFO / LRU พร้อมควบคุมทีละขั้น | `compare_start`, `show_side` |
| 11 Save | บันทึกข้อมูล → ชื่อ/ตำแหน่งไฟล์ และยืนยันเมื่อเขียนทับ | `save_file`, `save_path` |
| 0 Exit | ปุ่มออก หรือ X มุมหน้าต่าง | `WM_CLOSE` |

ปุ่มและหน้าต่างอยู่ใน `src/gui.c` ส่วน `src/simulator.c` และ `src/search.c` ใช้ logic เดิม ไม่ได้เปลี่ยน algorithm

ฟังก์ชันรับไฟล์ที่เปิดไว้แล้วใน `input.c` ช่วยให้ UI ใช้ `_wfopen` เพื่อโหลดไฟล์ที่พาธมีภาษาไทย โดยยังใช้ parser และ validation เดิม

## รายละเอียดการใช้งาน

- ทุกการเริ่มรันเริ่มด้วย frames ว่าง กดเริ่มทีละขั้นอีกครั้งเพื่อเริ่มรอบใหม่
- ตารางแสดง Hit/Fault ด้วยข้อความและสี เลือกแถวในหน้าจำลองเพื่ออ่านเหตุผลด้านล่าง
- หน้าจำลองใช้ algorithm ที่เลือก ส่วนหน้าเปรียบเทียบใช้ทั้งสามวิธีเสมอ
- หน้าเปรียบเทียบใช้จำนวน frames จากหน้าจำลอง คำอธิบายด้านบนแสดงค่าปัจจุบัน เลื่อนตารางแนวนอนเพื่ออ่านเหตุผลของ FIFO และ LRU
- สถิติและจุดที่เริ่มต่างกันในส่วนทีละขั้นนับเฉพาะขั้นที่แสดง ตารางสรุปด้านบนเป็นผลครบชุด
- การเปลี่ยนข้อมูลหรือ frames จะล้างผลเก่าเพื่อไม่ให้ผลการทดลองปะปนกัน
- หน้าค้นหาใช้ frames ของตัวเอง พบแล้วจึงเปิดใช้ข้อมูลและ frames นั้น โดยไม่เปลี่ยน algorithm
- ค้นหาใน worker thread เพื่อให้หน้าต่างตอบสนอง ไม่มีปุ่มยกเลิกกลางการค้นหา จำกัดสูงสุด 100,000 ชุดเหมือนเดิม
- แยกผล Match found / ตรวจครบไม่พบ / ถึง limit ชัดเจน สองกรณีหลังเก็บข้อมูลเดิมไว้
- เงื่อนไข 3 ใช้ base frames ได้ 1–9 เพื่อเทียบกับ F+1
- บันทึกเฉพาะ reference string ไม่เก็บ frames, algorithm หรือสถิติ โหลดใหม่แล้วตั้ง frames ให้ตรงกับรอบเดิม
- ชื่อไฟล์เริ่มต้นเป็น `result_001.txt` และเลือกชื่อถัดไปที่ยังไม่ใช้ ชื่อไฟล์และโฟลเดอร์ภาษาไทยรองรับผ่าน Windows file dialog
- ออกจากโปรแกรมขณะมีชุดข้อมูลจากการค้นหาที่ยังไม่บันทึก จะถามให้บันทึก ทิ้ง หรือยกเลิกการออก
- หน้าต่างย่อได้ถึงประมาณ 1100 × 850 พิกเซลที่ 100% scaling ตารางรองรับการเลื่อน เหมาะกับจอเดสก์ท็อป หากใช้ scaling สูงควรขยายหน้าต่างหรือใช้จอที่มีพื้นที่เพียงพอ

## รูปแบบข้อมูล

ไฟล์ `.txt` แบบ UTF-8 (มีหรือไม่มี BOM) ใช้จำนวนเต็มไม่ติดลบ 0 ถึง 2147483647 คั่นด้วยช่องว่างหรือขึ้นบรรทัดใหม่ สูงสุด 1,000 ตัว เช่น:

```text
0 0 1 0 2 3 1
```

ไฟล์ว่าง คอมมา เลขติดลบ และ UTF-16 จะไม่ผ่าน validation เมื่อโหลดไม่สำเร็จจะเก็บข้อมูลเดิมไว้

## Build เมื่อแก้โค้ด

ติดตั้ง GCC และ windres ของ MSYS2 UCRT64 แล้วรัน `build.bat` สคริปต์ตรวจตำแหน่ง `C:\msys64\ucrt64\bin` ให้อัตโนมัติ หากติดตั้งที่อื่นให้เพิ่มโฟลเดอร์ bin เข้า PATH

`build.bat` สร้าง GUI เป็น `memory_policy_lab.exe` ที่รากโปรเจกต์ `run.bat` เปิด EXE ที่มีอยู่ และ build เฉพาะเมื่อยังไม่มี EXE หากแก้โค้ดต้องเรียก build.bat เอง

ใช้ `build-cli.bat` หากต้องการสร้าง Terminal เวอร์ชันเดิมที่ `build/memory_policy_lab.exe` ชื่อไฟล์เหมือนกันแต่คนละตำแหน่งกับ UI

## การตรวจสอบ

รัน `test.bat` เพื่อ build GUI และ CLI ตรวจ engine, parser, search, results และ GUI smoke test

GUI smoke test เรียก event handlers และตรวจสถานะ controls จริง รวมการรัน/หยุด/เริ่มใหม่, FIFO 4 เทียบ LRU 5, Belady 9 เทียบ 10, worker search ทั้งสามผลลัพธ์, validation และ save/reload พาธภาษาไทย พร้อมภาพ render ทั้งสี่หน้าใน `build/gui-qa`

ตรวจ native file dialog ผ่านการเชื่อมกับ Windows API; smoke test ตรวจตัว load/save ที่อยู่หลัง dialog ไม่ได้จำลองการกดผ่าน file picker โดยมนุษย์

ไฟล์ EXE link runtime ของ GCC แบบ static และอ้างอิงเฉพาะ DLL ของ Windows จึงไม่ต้องนำ DLL ของ MSYS2 ไปด้วย
